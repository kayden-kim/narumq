# Artifact Design

## 목적과 적용 범위

독자가 글을 읽는 자리에서 그림으로 뜻을 확인할 수 있는 웹 문서를 만든다. 기본 단위는 카드가 아니라 **문단과 그 문단을 설명하는 시각 자료의 쌍**이다. 긴 문서 전체에 읽기 순서와 여백의 리듬을 만든다.

이 기준은 이 스킬로 만드는 아티팩트에 적용한다. 사용자 요청으로 편집 문서와 세로형 포스터 구성을 채택했다. 프로젝트의 기존 디자인 기준이 있으면 그 기준을 먼저 따른다. 특정 이미지 이름이나 출처를 결과물의 디자인 규칙으로 남기지 않는다.

## 먼저 정할 것

1. 독자가 이해해야 할 질문을 한 문장으로 적는다.
2. 실제 자료에서 사실과 예시를 구분한다. 수치, 성능 개선, 코드 경로를 임의로 만들지 않는다.
3. 설명 순서를 정한다. 예: 전체 모습 → 구성 요소 → 동작 → 차이와 한계.
4. 각 문단 옆이나 아래에 어떤 시각 자료가 필요한지 적는다. 그림의 캡션이 그 역할을 설명해야 한다.
5. 내용에 맞는 레이아웃과 스타일을 고른다. 여러 안을 요청받으면 같은 내용으로 비교한다.

## 편집 문서의 구성 원칙

- **한 장처럼 이어지는 문서**: 표지, 본문, 색상 구간과 맺음말을 연속으로 배치한다. 모든 문단을 둥근 카드에 넣거나, 문서를 KPI 대시보드처럼 바꾸지 않는다. 대시보드를 요청받았을 때만 그 형식을 쓴다.
- **크기가 다른 시각 자료**: 전체를 보여주는 큰 그림, 문단 옆의 중간 그림, 문장 사이의 작은 삽화를 섞는다. 같은 크기의 도식 상자만 반복하지 않는다.
- **비대칭과 여백**: 본문과 그림의 폭, 높이, 시작 위치를 다르게 준다. 독자가 읽을 수 있는 순서와 문단 폭은 유지한다. 빈 공간을 무조건 배지나 숫자로 채우지 않는다.
- **색상 구간**: 장면이나 질문이 바뀌는 곳에 전폭 색상 구간을 쓴다. 구간 전체가 그림의 바탕이 될 수 있다. 의미 없는 배경 패턴·선화·프레임은 넣지 않는다. 도식의 선과 화살표는 관계를 설명할 때만 쓴다.
- **부드러운 연결**: 소제목, 캡션, 짧은 인용문으로 다음 장면을 연결한다. 구분선이나 박스가 유일한 구획 수단이 되지 않게 한다.
- **목적이 있는 패널**: 인용문, 비교 대상, 세로형 포스터는 묶을 수 있다. 같은 외형의 카드가 모든 내용을 대신하지 않게 한다.
- **기울기는 전시 연출**: 실제 읽는 페이지 전체를 회전시키지 않는다. 화면을 비스듬히 보여주는 목업과 문서의 읽기 레이아웃을 구분한다.

## 레이아웃 변형

전체 문서의 구성과 개별 장면의 배치를 나누어 고른다. 구현 위치와 마크업은 [레이아웃 레퍼런스](references/layout-variations.md)를 읽는다.

### 전체 문서

| 변형 | 구조 | 적합한 설명 |
| --- | --- | --- |
| 연속 에세이 (`essay`) | 큰 표지 그림 → 폭이 다른 글·그림 → 색상 구간 → 결론 | 개념을 차근차근 이해하는 긴 글 |
| 분할 챕터 (`split`) | 표지부터 글과 큰 그림을 좌우로 배치. 본문은 균등한 2열과 가로 그림 묶음 | 설명과 시각 자료를 나란히 비교하는 글 |
| 사이드 노트 (`margin`) | 큰 제목 아래에 넓은 리드와 작은 보조 그림. 본문 오른쪽에는 좁은 주석 열을 고정 | 본문을 중심으로 읽으며 세부를 곁에서 확인하는 글 |

760px 이하에서는 읽기 쉬운 1열로 통합한다. 비교 선택기를 유지할 때는 현재 구성의 특징과 모바일 통합 상태를 바로 안내한다. 구성의 차이는 열 폭뿐 아니라 표지 그림의 위치, 그림 묶음과 주석 위치에서도 드러나야 한다.

### 개별 장면

1. **표지와 큰 장면**: 제목과 짧은 리드 다음에 넓은 사진·삽화·개념도를 놓는다. 그림 위에 수치 배지를 덧붙이지 않는다.
2. **교차 스프레드**: 글 옆에 세로 그림, 다음 문단 옆에는 가로 그림을 놓는다. 교차는 문맥에 따라 선택한다.
3. **주변 삽화**: 문단의 위·아래·여백에 작은 도식이나 개념의 일부를 배치한다. 본문 안으로 침범하지 않는다.
4. **콜라주와 갤러리**: 큰 그림 하나와 작은 관련 그림들을 묶는다. 각 그림은 세부 구조·사례 등 다른 정보를 제공한다.
5. **인용과 강조**: 핵심 문장을 여백 또는 색상 구간 안에 놓는다. 실제 인용이면 출처를 적고, 작성자의 요약이면 인용처럼 위장하지 않는다.
6. **세로형 포스터 쌍**: 상단에 작은 분류, 큰 제목과 짧은 설명을 놓는다. 아래에는 내용을 설명하는 사진이나 도식을 놓는다. 두 패널의 밝기·색상·장면을 대비시킨다. 장식용 실루엣은 넣지 않는다.

## 타이포그래피와 색상 팔레트

타이포그래피, 색상 팔레트, 읽기 구성을 각각 독립해 정한다. 아래 조합은 시작 예시다. 타이포그래피 스타일 하나에 특정 팔레트를 고정하지 않는다.

| 타이포그래피 스타일 | 활자·리듬 | 추천 시작 팔레트 (예시; 고정 아님) |
| --- | --- | --- |
| 에디토리얼 (`editorial`) | 한국어 명조 제목, 고딕 본문. 명조가 없으면 고딕으로 대체 | 종이·숲 |
| 미니멀 (`minimal`) | 절제된 산세리프 제목·본문, 넉넉한 여백 | 슬레이트 |
| 기술 문서 (`technical`) | 한국어 고딕 제목 700·본문 400, 넉넉한 제목 행간. 고정폭은 코드·영문 식별자에만 사용 | 청사진 |
| 볼드 포스터 (`bold`) | 굵고 큰 산세리프 제목, 짧은 소제목 | 감귤·황토 |

### 같은 타이포그래피 안의 색상 변형

| 색상 팔레트 | 색상 구성 |
| --- | --- |
| 종이·숲 (`paper-forest`) | 크림색 종이, 숲 초록, 벽돌색 강조 |
| 청사진 (`blueprint`) | 차가운 흰색, 짙은 파랑, 청색 강조 |
| 감귤·황토 (`citrus`) | 아이보리, 흙빛, 벽돌색 강조 |
| 야간 (`night`) | 짙은 남청 바탕, 밝은 글자, 살구색 강조 |
| 장미·회백 (`rose`) | 연분홍 종이, 자두색 글자, 장미색 강조 |
| 라일락·남색 (`violet`) | 연보라 종이, 남색 글자, 보라색 강조 |
| 바다·청록 (`ocean`) | 옅은 바다색, 짙은 청록, 테라코타 강조 |
| 슬레이트 (`slate`) | 회색 종이, 차콜 글자, 호박색 강조 |

- 새 아티팩트에서는 타이포그래피와 읽기 구성을 고정하고, 템플릿의 팔레트 8종 중 내용에 맞는 4종 이상을 비교한다. 대비와 그림의 조화를 확인한 뒤 하나를 선택한다.
- 한 가지 최종 결과만 요청받으면 팔레트 하나를 선택하고 이유를 짧게 밝힌다. 사용자가 여러 디자인 변형을 요청하면 타이포그래피·읽기 구성·내용은 고정하고 색상 팔레트가 다른 3개 이상의 완성된 안을 만든다. 가능한 조합을 전부 출력하지 않는다.

- 본문은 16px 이상으로 시작한다. 한 문단은 대략 45~75자 폭으로 제한한다. 한국어는 실제 화면에서 폭과 줄바꿈을 확인한다.
- 한국어 제목에 고정폭 폰트를 지정하지 않는다. 영문 고정폭 폰트에서 한글이 기본 대체 글꼴로 넘어가면 제목의 형태가 달라진다. `Gulim`·`굴림`을 제목의 기본값이나 대체 목록에 넣지 않는다.
- 한국어 고딕은 `Pretendard`, `Noto Sans KR`, `Apple SD Gothic Neo`, `Malgun Gothic`, `맑은 고딕` 순의 로컬 후보를 사용할 수 있다. 코드·영문 식별자에만 별도의 고정폭 폰트를 쓴다.
- 명조 제목은 `Noto Serif KR`, `Nanum Myeongjo`, `AppleMyungjo` 같은 한국어 글꼴을 우선한다. 로컬 명조가 없으면 한국어 고딕으로 대체한다. 외부 폰트가 없어도 읽을 수 있어야 하며, 설치 여부를 확인하지 않고 특정 폰트로 보인다고 보고하지 않는다.
- 본문 행간은 1.75~1.9, 제목은 1.3~1.45에서 시작한다. 기술 문서 제목은 1.4와 굵기 700을 기본으로 한다. 자간은 0~-0.02em 범위에서 확인하고, 과도하게 압축하지 않는다.
- 한국어 문단·제목에는 `word-break: keep-all`을 적용해 어절을 유지한다. 긴 URL·식별자 등은 `overflow-wrap: anywhere`로 넘침을 막는다. 모바일에서 긴 한글 제목을 실제로 확인한다.
- 기본 상태는 무장식이다. 의미 없는 선화·문양·배경 패턴·프레임·이중선을 추가하지 않는다. 설명에 필요한 도식의 선·화살표, 구조 구분선, 포커스 표시처럼 뜻이나 기능을 전달하는 선은 유지한다.
- 색상 팔레트는 `--paper`, `--ink`, `--muted`, `--accent`, `--rule`, `--wash` 같은 CSS 토큰으로 관리한다. 타이포그래피와 팔레트는 별도 선택 축으로 두고, 도식·캡션·컨트롤은 선택한 팔레트에 맞춘다.
- 일반 텍스트는 4.5:1, 큰 텍스트와 필수 도형·컨트롤은 3:1 이상의 대비를 확인한다. 색상 외에 라벨·선 형태로도 구분한다.

## 도식과 그림

[도표·도식 레퍼런스](references/diagrams-and-infographics.md)에서 질문에 맞는 형식을 선택한다.

- 문단 좌우에는 구조의 일부, 세부 형상, 비교 대상을 놓는다. 문단 위아래에는 전체 관계나 동작 흐름을 놓는다.
- 실제 사진·삽화가 있으면 내용을 설명하는 곳에 사용한다. 파일을 내장할 때 출처와 사용 조건을 확인한다. 자료가 없으면 의미가 분명한 SVG나 HTML 도식을 쓴다. 빈 사진 자리나 가짜 차트로 채우지 않는다.
- 모든 그림에 번호 또는 제목과 캡션을 준다. 관계도에는 연결의 뜻, 동작도에는 방향과 상태를 적는다.
- 같은 내용을 글·표·차트로 세 번 반복하지 않는다. 하나는 전체를, 다른 하나는 세부를 설명하게 한다.
- 도식은 어두운 상자 안에 격리하지 않아도 된다. 문서 바탕이나 색상 구간에 직접 그려 글과 연결한다.
- 동작·관계·순서·상태 변화가 핵심이면 Mermaid의 `flowchart`, `sequenceDiagram`, `stateDiagram-v2`에서 쓰는 노드·화살표·참여자 구획을 주요 시각 언어로 적극 활용한다. 긴 흐름은 큰 개요도와 관련 문단 옆의 작은 세부 도식으로 나눈다.
- 단일 HTML처럼 Mermaid 렌더러가 없는 결과물에서는 원시 Mermaid 코드를 노출하지 않는다. 같은 구성을 인라인 SVG나 의미 있는 HTML로 그리고 외부 CDN에 의존하지 않는다. 형식 선택은 [도표·도식 레퍼런스](references/diagrams-and-infographics.md)를 따른다.

## 인터랙션과 애니메이션

[인터랙션 레퍼런스](references/interactive-patterns.md)에 따라 정적 설명이 부족한 곳만 보완한다.

- 비교 선택은 바뀐 상태와 그 이유를 함께 보여준다. 여러 관점이 필요하면 탭, 노드별 책임이 필요하면 인스펙터를 쓸 수 있다. 기능을 모두 전시할 필요는 없다.
- 조작부는 도식 바로 아래나 가장자리에 아이콘 중심의 작은 도구줄로 묶는다. 지면에서 차지하는 면적은 작게 유지하되, 주요 동작은 악센트·테두리·초점 표시로 쉽게 찾게 한다.
- 일관된 인라인 SVG나 간단한 기호를 쓰고 이모지는 피한다. 아이콘만 있는 버튼에는 `aria-label`을 붙이고, 모바일 조작 영역은 44×44px 이상으로 확보한다. 현재 상태와 설명은 버튼과 분리해 읽을 수 있게 둔다.
- 시간 순서는 이전·다음 단계로 직접 탐색할 수 있게 한다.
- 움직이는 패킷은 요청 방향을, 돌아오는 응답은 결과 관계를 보여준다. 저장 완료를 설명하려면 저장 상태가 먼저 바뀌어야 한다. 이동만 보여주고 성공했다고 쓰지 않는다.
- 애니메이션의 속도는 설명용이라는 점을 밝힌다. 실제 지연이나 처리량을 뜻하는 것처럼 보이지 않게 한다.
- 자동 반복 대신 사용자가 시작하는 유한 재생을 기본으로 한다. 재생·일시정지·다시 시작을 제공한다. 반복이 필요하면 이유를 정한다.
- `prefers-reduced-motion: reduce`에서는 이동을 없애고 단계 선택과 정적 방향·상태를 남긴다. 버튼과 상태 문구도 정적 모드에 맞춘다.
- 재생 중 초기화·시나리오 변경을 하면 이전 동작을 취소한다. 오래된 완료 콜백이 새 상태를 덮지 않게 한다.

## 제작과 검증

1. 위 원칙으로 내용을 구성한 뒤 [단일 HTML 템플릿](assets/editorial-template.html)을 필요한 범위만 재사용한다.
2. HTML, CSS, 바닐라 JavaScript를 한 파일에 넣는다. 외부 빌드 도구나 네트워크 없이 열 수 있게 한다.
3. 템플릿의 레이아웃·스타일 선택기는 비교용이다. 최종 결과물에는 선택한 안만 남긴다. 비교 요청이면 선택기를 유지할 수 있다.
4. 모바일에서는 본문 다음에 관련 그림을 놓는다. 좁은 화면에서 도식 라벨을 지나치게 줄이지 않는다. 의미에 맞게 세로로 재배치한다.
5. 실제 브라우저에서 전체 읽기 흐름, 스타일·레이아웃 변형, 모바일, 키보드 포커스와 컨트롤을 확인한다.
6. 움직임·단계·시나리오 전환을 실행한다. 일시정지, 재개, 초기화, 빠른 연속 조작, 정적 모드와 오류 결과를 확인한다.
7. 최종 보고에 변경한 파일, 선택한 구성, 실제 확인 결과와 미실행 범위를 적는다. 템플릿의 예시 동작을 프로젝트 구현의 증거로 보고하지 않는다.
