# 레이아웃 변형 레퍼런스

## 적용 기준

[스킬의 편집 문서 원칙](../SKILL.md#편집-문서의-구성-원칙)을 따른다. 시각 값은 [타이포그래피와 색상 팔레트](../SKILL.md#타이포그래피와-색상-팔레트)에서 선택한다. 아래는 구조 규칙이다. 실행 가능한 전체 마크업과 CSS는 [템플릿](../assets/editorial-template.html)에 있다.

## 전체 문서의 변형

템플릿의 `body[data-layout]`이 `.cover`, `.spread`, `.gallery`와 주석의 위치를 바꾼다. 내용을 복제하거나 문단을 JavaScript로 이동하지 않는다. DOM의 읽기 순서는 제목 → 본문 → 관련 그림으로 유지한다.

| 값 | 표지 | 본문 |
| --- | --- | --- |
| `essay` | 제목·리드 아래에 넓은 그림을 놓는다. | 글·그림을 교차하고 콜라주를 비대칭으로 묶는다. |
| `split` | 제목·리드는 왼쪽, 큰 그림은 오른쪽에 놓는다. | 같은 폭의 2열과 가로로 나열한 그림 묶음으로 비교한다. |
| `margin` | 큰 제목 아래에 넓은 리드와 작은 보조 그림을 놓는다. | 본문을 넓히고 오른쪽의 좁은 주석 열에 그림을 세로로 쌓는다. 마지막 장면도 주석을 오른쪽에 유지한다. |

760px 이하에서는 세 구성 모두 제목 → 본문 → 그림의 1열 읽기 흐름으로 통합한다. CSS의 시각적 교차 순서는 해제하고 주석의 구분선도 제거한다. 그림과 캡션은 함께 이동한다. 선택기 아래의 `layoutNote`는 현재 선택의 특징을 설명하고, 좁은 화면이면 1열 통합 상태를 안내한다.

## 표지와 큰 장면

`.cover`는 작은 분류, 큰 제목, 짧은 리드와 넓은 개념 그림을 묶는다. `.cover-art`는 장면 자체를 보여준다. 그림을 테두리·배지·그림자가 있는 대시보드 위젯으로 바꾸지 않는다.

사진이면 큰 장면과 세부 사진의 역할을 나눈다. SVG면 전체 시스템의 역할만 보여주고, 다음 장면에서 설명할 세부 동작까지 모두 넣지 않는다.

## 교차 스프레드

```html
<section class="spread" aria-labelledby="chapter-title">
  <div class="prose">
    <p class="eyebrow">01 / 구조</p>
    <h2 id="chapter-title">문단이 답하는 질문</h2>
    <p>그림에서 확인할 관계를 설명한다.</p>
  </div>
  <figure class="side-figure">
    <!-- 실제 시각 자료 -->
    <figcaption>그림이 보여주는 범위와 생략한 세부를 적는다.</figcaption>
  </figure>
</section>
```

다음 장면에 `.spread--reverse`를 쓸 수 있다. 패턴을 맞추기 위해 교차하지 않는다. 전체 흐름과 주변 시각 자료를 함께 보고 판단한다.

## 콜라주와 주석

`.gallery`는 큰 관련 그림 하나와 작은 그림 두 개를 묶는다. 템플릿에서는 대기열 전체, 처리 중인 항목, 기록의 세부를 각각 보여준다. 같은 통계 카드를 크기만 바꿔 반복하지 않는다.

- 그림의 상단 높이를 일부 다르게 주어도 캡션은 해당 그림 바로 아래에 둔다.
- 작은 삽화는 제목의 모서리나 문단 사이에 놓을 수 있다. 독서 영역을 덮지 않는다.
- 배경이나 가장자리 그림은 내용을 설명할 때만 사용한다. 의미 없는 선화·실루엣·문양은 넣지 않는다.

## 인용과 색상 구간

`.chapter-band`는 새로운 질문이 시작되는 전폭 구간이다. 본문·도식·요약 문장이 그 바탕을 공유한다. 요약을 큰 글자로 보여줄 수 있지만, 출처 없는 말을 누군가의 인용으로 표시하지 않는다.

실제 인용문은 `blockquote`와 출처를 사용한다. 작성자의 정리는 `aside` 또는 본문으로 구분한다. 템플릿의 `.pull-note`는 작성자의 개념 요약이다.

## 세로형 포스터 쌍

`.feature-pair` 안의 두 `.feature`는 비교할 개념을 위한 긴 지면이다. 작은 분류 → 큰 제목 → 짧은 본문 → 이동 링크 → 하단 시각 자료 순서로 배치한다.

- 제목 위쪽과 그림 사이에 충분한 빈 공간을 둔다.
- 아래쪽에는 내용을 설명하는 큰 사진이나 도식을 놓는다. 사진을 자르더라도 핵심 의미와 라벨을 자르지 않는다. 장식용 실루엣은 넣지 않는다.
- 두 패널의 밝기와 색상은 대비시킨다. 글의 대비는 각각 확인한다.
- 좁은 화면에서는 두 패널을 세로로 쌓는다. 한 패널을 숨기거나 가로 스와이프를 요구하지 않는다.
- 이 구성은 비교 장면이다. 모든 문단을 같은 포스터에 넣지 않는다.

## 재사용 범위

타이포그래피(`body[data-style]`), 팔레트(`body[data-palette]`), 읽기 구성(`body[data-layout]`)은 각각 독립해 바꾼다. 같은 타이포그래피와 읽기 구성 안에서 팔레트만 비교할 수 있다. 기본 상태는 무장식이며 비교용 선택기는 최종 아티팩트에서 제거한다.

## 템플릿 검증 기록

이 기록은 템플릿을 확인한 환경에만 적용한다. 다른 프로젝트나 OS의 결과를 대신하지 않는다.

- 환경: Windows, Chrome 154.0.8037.98. 템플릿을 로컬 Python HTTP 서버로 제공했다.
- 4개 타이포그래피 × 8개 팔레트 × 1440px, 기술 문서 타이포그래피 × 8개 팔레트 × 390px·320px를 확인했다. 총 48개 조합에서 팔레트 변경은 제목의 글꼴 계열·굵기·크기·행간을 바꾸지 않았고, 가로 넘침이 없었다. 팔레트 8종은 서로 다른 종이색을 사용했다. 장식 선택기와 장식용 선화는 없다.
- 기술 문서 제목의 실제 렌더링 폰트는 CDP `CSS.getPlatformFontsForNode`로 확인했다. `Pretendard-Bold`가 사용됐다. 제목 굵기는 700, 행간은 글자 크기의 1.4배였다.
- 같은 환경에서 에디토리얼 제목은 `Noto-Serif-KR`, 미니멀 제목은 `Pretendard-Medium`, 기술 문서 제목은 `Pretendard-Bold`, 볼드 포스터 제목은 `Pretendard-Black`으로 렌더링됐다.
- 320px 화면에서 긴 한국어 제목의 어절 줄바꿈을 확인했다. 8개 팔레트의 본문 텍스트 토큰 대비 최솟값은 4.91:1이었고, 구분선과 종이색의 최솟값은 3.47:1이었다. 이 결과는 전체 접근성 적합성 판정이 아니다.
- 실제 버튼 조작으로 정상·기록 실패의 결과, 일시정지, 초기화와 시나리오 변경의 취소, 단계 범위, 모바일 재생, 키보드 단계 탐색, 실행 중 움직임 줄이기 전환을 확인했다.
- 한국어 폰트가 없는 환경, 다른 OS·브라우저, 스크린 리더의 읽기는 미실행이다. 로컬 폰트 대체 목록은 제공하지만 모든 환경에서 같은 글꼴을 보장하지 않는다.
