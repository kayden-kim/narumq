# 도표·도식 레퍼런스

## 선택 기준

[스킬의 도식과 그림 규칙](../SKILL.md#도식과-그림)을 따른다. 그림은 문단에 대한 답이다. 빈 공간을 채우는 용도가 아니다.

## Mermaid 같은 도식 문법

- 동작·관계가 중심인 해설에서는 흐름도, sequence, state 도식을 주요 설명 수단으로 적극 활용한다. 각 노드에는 짧은 이름을 쓰고, 화살표에는 메시지·조건·결과를 붙인다.
- 넓은 개요도와 문단 사이의 작은 세부 도식을 함께 쓸 수 있다. 같은 흐름을 크기만 바꿔 반복하지 않는다.
- HTML 결과 환경이 Mermaid를 실제로 렌더링하지 않으면 원시 Mermaid 코드를 남기지 않는다. 단일 HTML은 의미 있는 인라인 SVG나 HTML로 같은 문법을 표현하고 외부 Mermaid 런타임을 불러오지 않는다.


## 서로 다른 크기의 그림

[템플릿](../assets/editorial-template.html)에는 세 가지 크기와 역할이 있다.

- `.cover-art`: 생성, 대기, 기록의 역할을 풍경처럼 배치한다. 시간 순서를 재생하지 않는다.
- `.gallery`: 대기열의 전체와 처리·기록의 세부를 서로 다른 크기의 SVG로 묶는다. 각 그림에 독립된 캡션이 있다.
- `.mechanism`: 같은 요청이 어떤 상태를 거쳐 응답되는지 보여준다. 노드, 방향과 현재 단계를 라벨로 표시한다.

이들은 같은 그림의 복제본이 아니다. 전체 역할 → 부분의 구조 → 시간에 따른 상태를 나누어 설명한다.

## 사진과 삽화

실제 자료가 있으면 큰 장면, 세부 확대, 관련 사례를 조합한다. 파일을 내장할 때 출처와 사용 조건을 확인한다. 사진이 없으면 내용을 설명하는 벡터 도식을 만든다. 의미 없는 색 블록을 사진 자리라고 부르지 않는다.

설명에 기여하지 않는 배경 삽화·선화·잘라낸 실루엣은 넣지 않는다. 의미가 있는 SVG에는 `role="img"`, `title`과 `desc`를 연결한다.

## 선과 상태의 뜻

- 관계선은 연결의 뜻을, 화살표는 동작 방향을 나타낸다. 두 가지를 구분한다.
- 현재 단계는 강조색과 텍스트로 표시한다. 이미 지난 단계와 아직 오지 않은 단계도 라벨로 구분한다.
- 요청과 응답은 라벨로 구분한다. 색상만으로 방향이나 성공 여부를 설명하지 않는다.
- 기록되지 않은 요청에 성공 응답을 표시하지 않는다. 오류를 설명할 때는 성공 경로와 다른 결과를 적는다.
- 이동 속도를 실제 처리 시간처럼 보이게 하지 않는다. 설명용 모형이라는 점을 캡션에 적는다.

## 바탕과 팔레트

SVG의 `fill`·`stroke`에는 `var(--ink)`, `var(--accent)`, `var(--rule)`, `var(--paper)` 같은 템플릿 토큰을 쓴다. 그림을 위한 별도 고정 팔레트를 만들지 않는다. 문서 바탕·색상 구간·어두운 스타일에서도 라벨이 읽히는지 확인한다.

모든 그림을 독립된 박스로 가두지 않는다. 정보 관계와 동작 방향을 표현하는 선·화살표만 쓴다. 무장식 기본을 유지하고, 선 굵기는 역할과 가독성에 맞춘다.

## 모바일과 검증

- 의미가 있는 글자를 포함한 도식을 무조건 축소하지 않는다. `.mechanism`처럼 가로 관계를 세로 흐름으로 바꿀 수 있다.
- SVG의 `viewBox`는 그림의 크기를 정한다. 라벨의 실제 렌더링 크기도 확인한다.
- 캡션은 줄바꿈을 허용한다. 그림 번호와 설명이 따로 떨어지지 않게 한다.
- 실제 데이터가 없는 지표·개선율·스파크라인은 추가하지 않는다. 가상의 예시는 가상이라고 표시하며, 측정 결과처럼 쓰지 않는다.

애니메이션의 실행·취소·정적 모드 계약은 [인터랙션 레퍼런스](interactive-patterns.md)를 따른다.
