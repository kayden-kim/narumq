# 인터랙션 레퍼런스

## 적용 범위

[스킬의 인터랙션과 애니메이션 규칙](../SKILL.md#인터랙션과-애니메이션)을 따른다. 전체 실행 예시는 [템플릿](../assets/editorial-template.html)의 `.mechanism`과 끝의 스크립트에 있다. 분리된 코드 조각을 조합하는 대신 이 구현과 DOM을 함께 재사용한다.

## 정적 설명이 부족한 질문

| 질문 | 선택할 동작 |
| --- | --- |
| 어떤 일이 먼저 일어나는가? | 이전·다음 단계 |
| 요청과 응답은 어디로 이동하는가? | 사용자가 시작하는 유한 애니메이션 |
| 기록이 실패하면 결과는 어떻게 바뀌는가? | 시나리오 선택과 결과 문구 |
| 같은 구조를 다른 관점에서 읽으려면? | 필요한 경우에만 탭 |
| 특정 노드의 책임과 입출력은 무엇인가? | 필요한 경우에만 인스펙터 |

템플릿은 앞의 세 질문을 한 그림에서 설명한다. 탭, 인스펙터, 필터를 기능 목록처럼 모두 넣지 않는다.

## 예시 동작의 계약

템플릿은 실제 서비스가 아니라 요청·기록·응답의 관계를 보여주는 개념 모형이다. 실제 지연 시간이나 저장 엔진의 보장 범위를 뜻하지 않는다.

| 단계 | 정상 흐름 | 기록 실패 |
| --- | --- | --- |
| 0 | 요청을 보내기 전 | 요청을 보내기 전 |
| 1 | 요청이 대기열에 들어감 | 요청이 대기열에 들어감 |
| 2 | 기록 완료 | 기록하지 못함 |
| 3 | 성공 응답이 요청자에게 돌아옴 | 오류 응답이 요청자에게 돌아옴 |

- 단계 2가 끝나기 전에 성공 응답을 표시하지 않는다.
- 재생은 현재 단계부터 끝까지 한 번 진행한다. 마지막 단계에서 재생하면 처음부터 시작한다.
- 일시정지는 현재 이동을 멈춘다. 재개는 같은 이동을 이어 간다.
- 이전·다음은 이동을 취소하고 선택한 정적 단계로 간다. 끝에서는 다음, 시작에서는 이전을 비활성화한다.
- 다시 시작과 시나리오 변경은 진행 중인 이동을 취소한다. 시나리오 변경은 단계 0으로 돌아간다.
- 시나리오 변경은 자동 재시도를 구현하지 않는다. 결과의 차이만 설명한다.
- 빠르게 조작해도 이전 재생의 완료 처리가 새 상태를 덮지 않아야 한다.

## 구현 책임

- `render()`는 현재 단계의 라벨, 설명, 버튼 상태를 함께 갱신한다.
- `run()`은 유한 재생과 일시정지·재개를 처리한다.
- `stop()`은 현재 Web Animation을 취소하고 재생 세대를 바꾼다. 이전 비동기 완료 처리는 세대를 확인한 뒤 종료한다.
- `stepTo()`는 정적 단계 선택을, `setScenario()`는 정상·실패 전환을 처리한다.
- `prefers-reduced-motion`이 활성화되면 재생을 중단하고 이동 버튼을 숨긴다. 이전·다음과 상태 설명은 유지한다. 이 설정은 실행 중 변경도 반영한다.
- 화면 크기가 바뀌면 진행 중인 좌표 기반 이동을 취소한다. 현재 완료된 단계는 유지한다. 다음 재생은 바뀐 노드 위치를 다시 읽는다.

CSS와 JavaScript에서 같은 DOM의 ID를 사용한다. 이벤트·시간 종료만으로 상태를 추정하지 않고 실제 애니메이션 완료를 기다린다. 완료된 단계와 이동 중인 단계를 구분한다.

## 접근성과 독서 흐름

`button`, `select`, 앵커 등 기본 요소를 사용한다. 상태 설명은 `aria-live="polite"`로 제공한다. 설명 도식의 변경은 단계 라벨에도 반영한다. 이동 중인 도식 요소는 접근성 트리에서 숨긴다.

- 자동으로 움직이는 장면은 기본으로 쓰지 않는다. 컨트롤은 그림 바로 아래나 가장자리에 작은 아이콘 중심의 도구줄로 둔다. 지면에서 차지하는 면적은 작게 유지하되 주요 동작은 악센트 색·테두리·초점 표시로 눈에 띄게 한다.
- 일관된 인라인 SVG나 단순한 기호를 쓴다. 이모지는 피한다. 아이콘만 있는 버튼에는 `aria-label`을 제공하고, 터치 조작 영역은 44×44px 이상으로 둔다. 현재 단계와 설명은 컨트롤과 별도 상태 문구로 전달한다.

## 확인 시나리오

실제 브라우저에서 다음을 확인한다.

1. 정상 재생이 기록 완료 뒤 성공 응답으로 끝나는지 확인한다.
2. 기록 실패 재생이 오류 응답으로 끝나는지 확인한다.
3. 이동 중 일시정지 후 위치가 멈추고 재개 후 끝나는지 확인한다.
4. 재생 중 초기화와 시나리오 변경을 한 뒤 이전 완료 문구가 나타나지 않는지 확인한다.
5. 이전·다음과 빠른 연속 클릭으로 범위를 벗어나지 않는지 확인한다.
6. 정적 모드에서 이동이 없고 같은 내용을 단계로 확인할 수 있는지 확인한다.
7. 모바일의 세로 노드 배치에서 요청·응답 방향과 라벨이 유지되는지 확인한다.
