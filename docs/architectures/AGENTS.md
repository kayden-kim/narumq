# 아키텍처 문서 작성 규칙

[상위 규칙](../AGENTS.md)을 따르며 다음을 추가한다.

## 시작 템플릿

| 템플릿 | 사용할 질문 |
| --- | --- |
| [코드 지도](../templates/code-map.template.md) | 코드 위치·진입점·구성요소와 대표 요청의 흐름 |
| [모듈 설계](../templates/module-design.template.md) | 한 모듈의 내부 구조·데이터·처리 순서·초기화 |
| [관점별 아키텍처 문서](../templates/architecture-view.template.md) | 배포·보안·전환 계획 등 특정 구조 질문 |

코드 지도와 모듈 설계는 전체 구조에서 파일·함수까지 따라갈 수 있게 작성한다.

## 작성 규칙

- 한 문서는 하나의 구조 질문에 답한다. 외부 동작과 교환 형식은 관련 스펙·계약을 연결한다.
- 프로젝트마다 코드 지도 하나를 둔다. 코드가 있으면 실제 구조를 `Current`로 기록한다. 코드가 없으면 계획 경로를 `Target`으로 기록한다. 구현 후 경로·심볼·흐름을 대조하고 `Current`로 바꾼다.
- 모듈 설계는 내부 구조·데이터·처리 순서·초기화를 정한다. 구현 전에는 `Target`으로 작성하고 채택된 범위를 `Active`로 표시한다.
- 채택된 단계적 전환은 `Transitional`로 표시한다. 현재 코드와의 차이·전환 계획을 기록한다. 구현이 설계와 일치하면 `Current`로 바꾼다.
- 설계 선택의 별도 기록은 [ADR 작성 조건](../decisions/AGENTS.md)을 따른다. 기준과 코드의 충돌은 [상위 규칙](../AGENTS.md#기준-문서-적용과-충돌-처리)을 따른다.
- 코드 위치는 저장소 기준 파일 경로와 심볼(클래스·함수 이름)로 적는다. 자주 바뀌는 줄 번호는 적지 않는다.
- 코드의 구조나 흐름이 바뀌면 코드 지도와 관련 모듈 설계를 같은 변경에서 갱신한다.
- 현재 구조(`Current`)와 목표 구조(`Target`)를 한 다이어그램에 섞지 않는다.
- 다이어그램의 모든 화살표 의미(호출, 데이터 전달, 처리 순서, 의존 관계)를 밝히고 의존 방향과 경계를 함께 설명한다.
- 코드 구조는 클린 아키텍처를 따라야 한다. 클린 아키텍처는 업무 규칙을 중심에 두고, UI·DB·외부 서비스 같은 바깥 레이어가 안쪽 레이어에 의존하게 하는 구조다. 안쪽 레이어는 바깥 레이어를 알지 못한다.
- 의존은 단방향이어야 하고, 레이어 사이의 경계는 명확해야 한다.
- 레이어 목록, 레이어별 허용 의존, 경계, 의존 위반 확인 방법(도구 또는 리뷰)은 코드 지도의 레이어 표에 기록해야 한다.
- 이 구조에서 벗어나려면 [ADR](../decisions/AGENTS.md)을 작성해야 한다.
- 구현 대조 상태와 증거는 [검증 기록](../AGENTS.md#검증-기록)을 따른다.
