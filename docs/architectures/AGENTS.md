# 아키텍처 문서 작성 규칙

[상위 규칙](../AGENTS.md)을 따르며 다음을 추가한다.

- 한 문서는 하나의 구조 질문에 답하며, 새 요구사항이나 결정을 구조 문서에서 만들지 않는다.
- 현재 구조(`Current`)와 목표 구조(`Target`)를 한 다이어그램에 섞지 않는다.
- 다이어그램의 모든 화살표 의미(호출, 데이터 전달, 처리 순서, 의존 관계)를 밝히고 의존 방향과 경계를 함께 설명한다.
- 구현 증거 대조 없이 상태를 `Verified`로 표시하지 않는다.
- `project-structure.md`의 코드 지도 절은 실제 CLI·listener 진입점과 대표 호출 흐름을 찾게 한다. 같은 문서의 `Target repository tree`는 별도 목표 구조이므로 실제 구현으로 표현하지 않고, Current라고 적은 경로·진입점은 실제 파일과 심볼을 대조한다.
- 모듈 설계는 한 모듈의 내부 책임·자료 흐름·상태 소유·초기화·오류 처리를 다룬다. 사용자에게 보이는 동작, wire 형식, 여러 모듈에 걸친 기술 선택을 새로 정의하지 않고 관련 스펙·contract·ADR을 연결한다.
- 파일 이동, 진입점·호출 순서, 상태 흐름이 바뀌면 코드 지도와 영향받는 모듈 설계를 함께 갱신한다.
