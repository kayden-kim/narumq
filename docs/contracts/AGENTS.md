# 계약 작성 규칙

[상위 규칙](../AGENTS.md)을 따르며 다음을 추가한다.

## 시작 템플릿

[계약 템플릿](../templates/contract.template.md)으로 교환 형식과 호환성을 작성한다.

## 작성 규칙

- 스키마(OpenAPI, JSON Schema 등)가 있으면 그 파일을 형식의 기준으로 삼는다. Markdown에는 목적·의미·호환성 규칙만 적고 스키마를 복제하지 않는다.
- 호환성을 깨는 변경(Breaking change)은 새 major 버전, 마이그레이션 및 롤백 계획을 함께 수립한다.
- 만드는 쪽(Producer)과 사용하는 쪽(Consumer)의 계약 테스트(Contract test)를 연결한다. 계약 테스트는 교환 데이터가 약속한 형식과 규칙을 만족하는지 확인한다. 결과와 증거는 [검증 기록](../AGENTS.md#검증-기록)을 따른다.
- 비밀 값이나 실제 인증 정보를 예시에 넣지 않는다.
