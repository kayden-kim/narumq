먼저 볼 것

세 경계를
섞지 않는다

TCP는 바이트를 전달합니다. MQTT ACK는 broker와 한 client 사이의 protocol 교환입니다. Cluster commit은 구성된 상태 변경의 복제 경계입니다. 각 사실은 서로를 대신하지 않습니다.

관찰한 것그 사실이 뜻하는 것
TCP read가 성공소켓에서 일부 바이트를 읽었습니다. 전체 MQTT packet이 도착했거나 처리됐다는 뜻은 아닙니다.
Decoder가 packet 반환완전한 MQTT control packet 하나를 해석했습니다. 해당 작업의 성공 ACK가 기록됐다는 뜻은 아닙니다.
Publisher가 PUBACK·PUBREC·PUBCOMP 수신publisher와 broker 사이 inbound 교환의 protocol 상태를 나타냅니다. subscriber 애플리케이션이 메시지를 사용했다는 증거는 아닙니다.
Cluster durable 경계 통과해당 QoS 경로가 요구하는 delivery commit 또는 target 없는 QoS 1의 quorum barrier를 통과했습니다. Production 저장 장치의 전원 손실 보장은 별도입니다.

핵심: Cluster QoS 1/2 성공 ACK는 적용된 durable 상태 경계 뒤에 옵니다. Standalone의 session·queue는 process-local 메모리 상태입니다.

02 / 입력

TCP는 frame을 보장하지 않는다.
Adapter가 packet 경계를 만든다

TCP는 연속된 byte stream입니다. 한 번의 read에 packet 일부만 올 수 있고, 여러 packet이 한 buffer에 이어질 수도 있습니다. Frame reader와 decoder가 경계를 나눕니다.

`readLoop`는 buffer에 있는 byte를 반복해서 Decoder에 넘깁니다. 불완전한 packet이면 다음 read를 기다리고, 완전한 packet이면 decoder가 반환한 길이만 소비합니다.

  1. 1frameReader수신 byte를 보관합니다. buffer가 차면 packet limit까지 확장하고, 남은 byte가 없으면 초기 크기로 돌아갑니다.
  2. 2Decoder.Decodefixed header와 Remaining Length를 검사하고 완전한 packet 하나를 해석합니다. 미완성 입력은 ErrIncompletePacket을 돌려줍니다.
  3. 3consume이번 packet byte만 제거합니다. 뒤에 붙은 packet은 다음 반복에서 해석합니다.
internal/domain/mqtt/decoder.go · Decoder.Decode 발췌
if remainingLength > len(src)-frameHeaderLength {
    return nil, 0, ErrIncompletePacket
}
body := src[frameHeaderLength : frameHeaderLength+remainingLength]

// packet type별 decoder를 호출

return packet, frameHeaderLength + remainingLength, nil

중간 packet type switch는 생략했습니다. 반환값의 두 번째 값은 이번 packet이 사용한 byte 수입니다.

internal/adapters/tcp/server.go · readLoop 발췌
if !connected {
    connectPacket, ok := packet.(*mqtt.Connect)
    if !ok {
        return ErrProtocol
    }
    if err := connection.activate(*connectPacket); err != nil {
        return err
    }
    connected = true
    version = connection.version
}

연결에서 첫 MQTT packet은 CONNECT여야 합니다. 이후 packet은 현재 protocol version으로 해석하고 해당 handler로 보냅니다. 소켓의 byte read 자체는 MQTT ACK가 아닙니다.

CONNECT 호출 경로

readLoop → activate → UseCase.ConnectContext 순서입니다. Application은 protocol·client ID와 인증정보를 확인하고 tenant principal을 만듭니다. 인증, Client ID binding, Will 권한 검사가 끝나기 전에는 session·route·queue를 바꾸지 않습니다.

그 뒤 기존 session을 읽고 열거나 새 session을 만듭니다. Cluster mode는 ownership을 얻고 durable delivery 상태를 attach하며 detached QoS 0을 claim합니다. 실패하면 성공 CONNACK을 반환하지 않습니다.

TCP adapter는 inbound/outbound inflight 상태를 복구한 뒤 CONNACK을 기록하고 write 완료를 기다립니다. 그 다음 delivery block을 풀어 recovered packet을 보냅니다.

03 / 구독

SUBACK을 쓴 뒤에야
retained replay가 출발한다

Retained message는 새 구독자가 나중에 받아볼 마지막 값을 저장합니다. Replay는 현재 SUBSCRIBE가 만든 delivery이므로 writer를 잠시 막아 응답 순서를 지킵니다.

코드가 지키는 순서

server.go는 SUBSCRIBE에서 delivery를 block하고 writer barrier를 기다립니다. SubscribeCommitted는 filter와 option을 검증하고, 필요하면 cluster subscription commit을 완료합니다.

subscribeOne은 retained replay 조건을 계산합니다. Batch를 queue에 넣고 local route를 적용한 뒤 결과를 돌려줍니다. Adapter는 SUBACK write 완료를 기다린 다음 block을 풉니다.

코드dispatch · SUBSCRIBESubscribeCommitted / subscribeOne / retainedBatch

Retain Handling

이 option은 live delivery가 아니라 SUBSCRIBE가 시작하는 retained replay 시점을 고릅니다. 공유 구독은 이 replay를 하지 않습니다.

0 · 항상구독 요청 때 matching retained 값을 보냅니다.
1 · 새 filter만해당 exact filter가 처음 생길 때 보냅니다.
2 · 보내지 않음새 retained replay를 생략합니다.

Replay QoS는 저장된 QoS와 subscription granted QoS 중 낮은 값입니다. Replay packet에는 RETAIN flag를 둡니다.

04 / 발행

PUBLISH는 먼저 경로를 고른다.
ACK 규칙은 QoS와 모드가 정한다

Application이 topic과 권한을 확인하고 route match를 만든 뒤 전달 경로를 선택합니다. Retained 입력은 저장 변경이 먼저 commit되거나 적용된 뒤 live match를 계산합니다.

입력 경로처리 경계Publisher가 받는 결과확인 범위

Standalone

Dynamic cluster
QoS 2		RECEIVE를 PUBREC 전에 commit합니다. PUBREL 뒤 RELEASE와 target queue 경계를 통과한 다음 완료합니다.RECEIVE 뒤 PUBREC; RELEASE 뒤 PUBCOMPInbound handshake state와 durable target delivery를 복구합니다. Consumer 애플리케이션 exactly-once 처리를 주장하지 않습니다.

Retained 값: tenant와 exact topic을 key로 저장합니다. 비어 있지 않은 payload는 값을 교체하고, zero-byte payload는 저장 값을 삭제합니다. Retained mutation 오류가 나면 그 PUBLISH는 fan-out으로 진행하지 않습니다.

Standalone과 Cluster는 저장 의미가 다르다

Standalone의 memory retained repository와 delivery queue가 process-local authority입니다. Dynamic cluster에서는 retained·offline·durable delivery state의 authority가 committed cluster state이고, local repository와 queue는 lookup·writer용 projection입니다.

Cluster QoS 1/2는 non-retained 입력에서 phase worker를 사용할 수 있습니다. Retained QoS 1/2는 동기 dispatch 경로를 거치며, application은 retained commit을 route match보다 앞에 둡니다.

Effective QoS 0은 다른 lane

Publish QoS가 1 또는 2여도 구독자가 허용한 QoS가 0이면 해당 대상은 at-most-once lane으로 갑니다. Cluster QoS 1/2 command는 durable target 상태를 commit하지만, QoS 0 live forwarding 자체에 수신 ACK나 retry가 추가되지는 않습니다.

05 / 기계

QoS 2는 한 번의 ACK가 아니다.
두 번의 commit 경계다

아래 sequence diagram은 dynamic cluster의 non-retained inbound QoS 2를 따라갑니다. 점은 선택한 시점을 가리킵니다. 작은 화살표 control은 단계 이동과 재생을 합니다.

중복과 Packet Identifier

Broker는 packet identifier별 inbound 상태를 유지합니다. 완료된 exchange의 tombstone은 반복 PUBREL을 멱등 처리합니다. 같은 identifier를 새 PUBLISH에서 재사용하면 기존 완료 상태를 새 exchange로 교체합니다.

Cluster durable connection은 두 phase lane으로 처리하고 같은 방향·identifier 순서를 보존합니다. 독립된 identifier의 durable I/O는 겹칠 수 있지만 성공 ACK는 각 완료 결과 뒤에만 나옵니다.

이것이 보장하지 않는 것

Publisher가 받은 PUBCOMP는 broker의 RELEASE 처리 경계입니다. Subscriber 애플리케이션이 payload를 한 번만 기록했거나 외부 side effect를 한 번만 수행했다는 증거가 아닙니다.

Target이 없더라도 Cluster QoS 2는 RECEIVE와 RELEASE 상태를 commit합니다. QoS 1 target이 없는 경우에는 별도 ReadIndex barrier를 사용합니다.

06 / 복구

재연결 복구와 process 재시작은
같은 말이 아니다

Persistent session은 network connection 종료 뒤에도 session state를 유지할 수 있습니다. 어떤 장애 뒤까지 남는지는 state adapter와 실행 모드가 결정합니다.

실행 모드연결 종료 뒤복구 경로와 제한
Standalone동일 process가 살아 있으면 session과 queued/inflight delivery state를 process-local memory에서 이어갑니다.Reconnect 때 CONNACK을 먼저 기록합니다. Recovery writer는 미완료 QoS PUBLISH에 기존 Packet Identifier와 DUP=1을 사용하고, QoS 2가 PUBREL 대기 상태면 같은 identifier의 PUBREL을 재개합니다. Process restart·replication 복구는 아닙니다.
Dynamic clusterOwnership과 delivery state를 committed cluster state로 복구할 수 있습니다. Detached QoS 0 offline queue와 durable QoS 1/2 session state는 서로 다른 lane입니다.새 owner가 attach한 상태를 TCP adapter에 복원하고 CONNACK 뒤 recovered packet을 재개합니다. 기록된 acceptance는 제한된 process test와 backup v3 restore에 한정됩니다.

Writer가 복구 packet을 먼저 다룬다

CONNECT activation은 outbound 상태를 읽어 Packet Identifier를 예약하고, 회복할 항목을 정렬합니다. Writer는 새 queued message보다 recovered state를 먼저 확인합니다.

internal/adapters/tcp/server.go · writeRecoveredDeliveries 발췌
packet.Version = connection.version
packet.DUP = true

if err := connection.writePacket(packet); err != nil {
    return err
}

복구된 PUBLISH 단계의 packet입니다. 이미 PUBREC까지 끝난 QoS 2 상태는 PUBREL로 이어집니다.

Backup은 별도 계약이다

NMQBKUP3 backup v3 contract는 retained state, detached QoS 0 offline queue, durable QoS 1/2 delivery session과 inflight state를 archive 범위에 둡니다. Archive 포함 여부만으로 production storage의 power-loss 보장을 주장할 수는 없습니다.

Cluster backup v3 contract와 MQTT·Cluster implementation spec은 현재 문서에서 Draft로 표시됩니다. Accepted ADR은 각 결정의 제한된 범위에만 적용됩니다.

07 / 증거

무엇을 시험했고,
무엇은 아직 주장하지 않는가

아래는 코드와 저장소 문서에 기록된 검증 결과입니다. 이 아티팩트 작업 중 Go 시험을 다시 실행하지 않았습니다.

Cluster spec §11.11은 focused package suite와 네 process acceptance test의 PASS를 기록합니다. Process test는 실제 broker process와 MQTT socket으로 reconnect, takeover, backup restore, ACK 뒤 process kill, quorum loss 동작을 관찰합니다.

  • TestTCPDurableQoS1WithoutTargetAcknowledgesAfterQuorumBarrierQuorum barrier가 끝나기 전에는 PUBACK을 보내지 않고, 성공 완료 뒤에만 ACK를 보냅니다.
  • TestTCPDurableQoS2ReceiveReleaseAndCapacityRECEIVE 전에 PUBREC을 보내지 않고, RELEASE commit 전에 PUBCOMP을 보내지 않는 경계를 확인합니다.
  • TestDynamicClusterDurableQoSTakeoverProcessAcceptanceDetached QoS 1/2 delivery와 owner takeover 뒤 session state 재개를 확인합니다.
  • TestDynamicClusterDurableQoSAckThenKillProcessAcceptance성공 PUBACK 뒤 publisher process를 중단하고 subscriber reconnect에서 committed message를 확인합니다. Quorum loss 중 성공 ACK가 없는 경로도 확인합니다.
  • TestDynamicClusterDurableQoSBackupRestoreProcessAcceptanceBackup restore 뒤 inflight QoS state와 inbound tombstone을 사용하며 duplicate subscriber delivery가 생기지 않는지 확인합니다.
  • TestDynamicClusterDurableQoS2WillProcessAcceptanceQoS 2 Will과 reconnect/takeover sequence의 제한된 process acceptance를 확인합니다.

이 증거가 승인하지 않는 범위

미주장 Production storage·EBS의 물리 전원 손실, BP-03, N-1 compatibility, TEN-08 tenant quota, broker drain/SAFE_TO_STOP 완료. Process acceptance와 backup restore 성공만으로 이 조건을 대신할 수 없습니다.

현재 MQTT protocol/session spec과 Cluster session/delivery spec은 Draft입니다. ADR-0015는 cluster QoS 1/2 durable delivery의 제한된 범위를 Accepted로 정하며, ADR-0019는 target 없는 publish의 빈 delivery command 생략 경계만 대체합니다.
