# 디자인 문서 작성 규칙

[상위 규칙](../AGENTS.md)을 따르며 다음을 추가한다.

이 디렉터리는 화면의 시각 산출물을 둔다. 디자인 시스템(`DESIGN.md`)과 화면 스펙별 HTML 시안이 여기에 있다. 화면의 동작·상태·수용 테스트는 [스펙](../specs/AGENTS.md)이 소유한다. 디자인 기준을 코드에 적용하는 규칙은 [프런트엔드 컨벤션](../conventions/AGENTS.md)이 소유한다.

작업 순서와 단계별 채택 기준은 [frontend-workflow 참고 문서](../../.agents/skills/frontend-workflow/references/frontend-workflow.md#4-디자인-탐색과-대표-화면)를 따른다.

## 시작 템플릿

| 템플릿 | 사용할 질문 |
| --- | --- |
| [디자인 시스템](../templates/DESIGN.template.md) | 공통 토큰·시각 원칙·컴포넌트 스타일과 예외 |

## 디자인 시스템

- 프로젝트마다 `docs/design/DESIGN.md` 한 파일을 둔다.
- 참고 디자인은 `DESIGN.md`의 "참고 자료" 항목에 기록한다. 별도 참고 자료 폴더를 만들지 않는다.

## HTML 시안

HTML 시안은 화면의 시각 구성을 브라우저에서 보여 주는 산출물이다.

- 화면 스펙 하나마다 `docs/design/mockups/<화면 스펙 파일 이름>.html` 한 파일을 둔다. 화면 스펙 파일 이름은 확장자를 `.html`로 바꿔 쓴다.
- 화면 스펙의 헤더 표 `HTML 시안` 항목에서 이 파일을 링크한다.
- `mockups/`에는 별도 README를 두지 않는다. 시안을 추가·이름 변경·삭제하면 같은 변경에서 [디자인 목록](README.md)과 화면 스펙의 헤더 표를 함께 고친다.
- 화면 스펙의 "화면 상태" 표에 있는 모든 화면 ID와 상태를 한 파일에 보여 준다. 각 화면에 화면 ID와 상태 이름을 표시한다.
- 시안과 스펙 문장이 다르면 스펙 문장을 따른다. 시안은 동작·상태·검증의 기준이 아니다.
- 시안은 `DESIGN.md`의 토큰만 사용한다. CSS 사용자 지정 속성(custom property)의 이름은 `DESIGN.md` 토큰 이름을 따른다. 임의의 색·간격 값을 쓰지 않는다.
- 시안은 외부 CDN과 네트워크 요청 없이 열리는 단일 HTML 파일이어야 한다.
- 스펙이 정한 경계 콘텐츠(긴 한글, 빈 값 등)가 있으면 해당 화면에 포함한다.
- 시스템 스펙의 화면 절은 텍스트 와이어프레임을 쓴다. 시안이 필요하면 그 스펙 파일 이름으로 같은 규칙을 적용한다.
