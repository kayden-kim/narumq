# 요구사항 문서 작성 규칙

[상위 규칙](../AGENTS.md)을 따르며 다음을 추가한다.

- 각 독립 요구사항에는 재사용하지 않는 안정된 ID를 부여한다.
- ID 하나에는 하나의 검증 가능한 결과만 둔다.
- 구현 방법보다 사용자나 운영자가 관찰할 결과를 먼저 쓴다.
- 목표와 비목표를 함께 기록한다.
- 모호한 표현 대신 측정 조건, 지표와 임계값을 쓴다.
- 수치가 미정이면 임의 값을 넣지 말고 미결정 사항으로 기록한다.
- 의미나 우선순위가 바뀌면 버전과 변경 근거를 갱신한다.
- 상세 동작은 `specs/`, 정확한 형식은 `contracts/`, 기술 선택은 `decisions/`로 분리한다.

## 추가 작성 지침

- **요구사항 ID 관리:** 변경되지 않는 고유 ID를 부여하며, 폐기 시 ID를 재사용하지 않고 폐기 상태와 사유를 기록한다. 단일 수용 시험으로 판정 불가 시 세부 ID로 분리하고 spec, contract, test에서 동일 ID를 추적한다.
- **우선순위 및 수용 기준:** 우선순위(P0/P1/P2)는 구현 순서가 아닌 release 필요 수준을 의미한다. P0 요구사항은 자동화된 수용 시험과 연결한다.
- **미결정 사항 처리:** 수치가 확정되지 않은 경우 임의 기본값을 쓰지 않고 미결정 사항, 확정 책임자 및 시점을 기록한다.
