# 검증 기록 작성 규칙

이 파일은 `docs/verification/`에 적용한다. [문서 작성 규칙](../AGENTS.md)과 함께 적용하며, 충돌하면 이 파일을 우선한다.

## 이 폴더를 두는 이유

[검증 기록](../AGENTS.md#검증-기록) 규칙에 따라 스펙에는 시나리오와 기대 결과만 둔다. 테스트 연결과 결과는 [테스트 컨벤션](../conventions/test-conventions.md)의 시나리오 보고서가 생성한다. 생성 보고서로 대신할 수 없는 과거 실행 기록은 이 폴더에 보존한다. EKS·kind 실측, 수동 운영 검증, 실패 기록이 해당한다.

## 작성 규칙

- 스펙 하나에 기록 문서 하나를 둔다. 파일 이름은 스펙과 같게 한다. 예: `specs/drain-and-rolling-update.md`의 기록은 `verification/drain-and-rolling-update.md`에 둔다.
- 기록마다 대상 시나리오 ID를 적는다. 시나리오의 기준 정의는 스펙에만 둔다.
- 기록에는 대상 버전·변경 범위, 환경, 명령 또는 확인 방법, 실제 결과를 적는다. 실행 결과는 `통과`·`실패`·`미실행`으로 표시한다. 미실행은 이유와 영향을 적는다.
- 현재 기준·제약·추적에 필요한 과거 기록만 유지한다. 대체된 중간 실행, 중복 수치와 작업 과정을 삭제하거나 간소화할 수 있다. 유효한 실패·미실행 사유·결정 근거는 남기고 실제 결과를 바꾸지 않는다. 후속 일부 시험의 통과로 미해결 실패를 해제하지 않는다.
- 커밋이나 테스트 파일 링크만으로 통과를 표시하지 않는다.
- 동작 정의, 불변식, 한계값과 기대 결과를 이 폴더에 새로 정하지 않는다. 스펙을 링크한다.
