# 시스템 스펙 작성 규칙

[상위 규칙](../AGENTS.md)을 따르며 다음을 추가한다.

- 외부 actor, 선행 조건, 상태, 입력과 관찰 가능한 결과를 정의한다.
- 정상 흐름뿐 아니라 거절, timeout, retry, 중단과 복구를 정의한다.
- “해야 한다”는 필수, “해서는 안 된다”는 금지, “권장한다”는 예외 가능, “할 수 있다”는 선택 동작에만 쓴다.
- 하나의 규범 문장에는 하나의 판정만 둔다.
- 정확한 encoding과 schema는 `contracts/`로 분리한다.
- 기술 선택과 구현 구조는 각각 `decisions/`와 `architectures/`로 분리한다.
- 각 규범 동작을 요구사항 ID와 수용 시험에 연결한다.

## 추가 작성 지침

- **동시성 및 분산 상태:** 동시·중복 요청에 대해 idempotency와 충돌 결과를 명시한다. 분산 상태는 소유권, commit 경계, fencing 및 `unknown` 상태 처리를 명시한다.
- **오류 처리 및 보안:** 오류는 안정된 분류, 재시도 가능 여부와 상태 변경 여부를 명시한다. 실패를 성공으로 응답하거나 `unknown`을 정상으로 취급해서는 안 된다. 내부 구현 세부 정보나 secret이 외부 오류에 노출되지 않도록 한다.
- **표준 프로토콜 식별:** 표준 프로토콜 명세와 NaruMQ가 자체 추가한 제약을 명확히 구분한다.
