# 스펙(동작 명세) 작성 규칙

[상위 규칙](../AGENTS.md)을 따르며 다음을 추가한다.

- 정상 흐름뿐 아니라 거절, 타임아웃, 재시도(Retry), 복구, 항상 지켜야 할 규칙인 불변식(Invariant)을 각각 별도 시나리오로 정의한다.
- 시나리오 ID는 문서 내 고유하게 유지하고 재사용하지 않으며, 다른 문서에서는 문서 경로와 함께 참조한다.
- “해야 한다”(필수), “해서는 안 된다”(금지) 등 규범 문장에는 하나의 판정만 둔다.
- 데이터 형식은 `contracts/`, 구조는 `architectures/`, 기술 선택은 `decisions/`로 분리한다.

## 화면 스펙 선택 기준

화면이 있는 기능은 화면 상태, 입력 검증, 화면 이동을 스펙 시나리오로 정의한다. 다음 중 하나라도 해당하면 [화면 스펙 템플릿](../templates/screen-spec.template.md)으로 별도 화면 스펙을 만들고, 해당하지 않으면 [시스템 스펙 템플릿](../templates/system-spec.template.md)의 "화면 구성과 와이어프레임" 절을 쓴다.

- 이 기능에 속한 화면이 3개 이상이다.
- 조건에 따라 서로 다른 화면으로 이동하는 분기가 있다.
- 검증 규칙이 있는 입력 항목이 3개 이상이다.
- 화면 크기(모바일·데스크톱 등)에 따라 배치나 동작이 다르다.

별도 화면 스펙을 만들면 화면 동작과 그 수용 시험 행은 화면 스펙에만 둔다. 관련 시스템 스펙과 PRD는 화면 스펙 경로와 시나리오 ID만 연결하고, 화면 동작이나 시험 행을 복제하지 않는다.

와이어프레임은 Markdown 텍스트 그림과 구성 요소 표로 작성한다. Figma 등 디자인 원본은 그림을 복사하지 않고 링크와 버전 또는 확인일로 연결한다.
