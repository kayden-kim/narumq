## 작성 규칙

- 정상 흐름과 적용되는 거절·타임아웃·재시도·복구를 별도 시나리오로 정의한다. 불변식(Invariant)은 항상 지켜야 할 규칙이며, 이를 확인할 시나리오도 작성한다.
- 시나리오 ID는 문서 내 고유하게 유지하고 재사용하지 않으며, 다른 문서에서는 문서 경로와 함께 참조한다.
- “해야 한다”(필수), “해서는 안 된다”(금지) 등 규범 문장에는 하나의 판정만 둔다.
- 데이터 형식은 `contracts/`, 구조와 모듈 내부 설계는 `architectures/`, 기술 선택은 `decisions/`로 분리한다.
- 시나리오의 테스트 연결과 커버리지·결과 보고는 [검증 기록](../AGENTS.md#검증-기록)을 따른다. 로그 본문은 복사하지 않는다.
- 업무 용어는 [용어집 유지보수](../AGENTS.md#용어집-유지보수)에 따라 스펙을 쓰는 시점에 확정한다.
- 화면 기능은 상태·입력 검증·화면 이동을 시나리오로 정의한다. 다음 중 하나라도 해당하면 별도 화면 스펙을 작성한다. 나머지는 시스템 스펙의 "화면 구성과 와이어프레임" 절을 쓴다.
  - 이 기능에 속한 화면이 3개 이상이다.
  - 조건에 따라 서로 다른 화면으로 이동하는 분기가 있다.
  - 검증 규칙이 있는 입력 항목이 3개 이상이다.
  - 화면 크기(모바일·데스크톱 등)에 따라 배치나 동작이 다르다.
- 별도 화면 스펙이 화면 동작과 수용 테스트를 소유한다. 관련 스펙과 PRD는 그 경로·시나리오 ID를 링크한다. 내용을 복제하지 않는다.
- 와이어프레임은 에이전트와 사람이 모두 읽고 변경을 비교할 수 있도록 Markdown 안의 텍스트 그림과 구성요소 표로 쓴다. 기준은 스펙의 문장과 수용 테스트 표이며, 와이어프레임과 다르면 문장을 따른다. HTML 시안이 있으면 텍스트 그림은 생략할 수 있다. 구성요소 표는 생략하지 않는다.
- HTML 시안의 위치와 작성 규칙은 [디자인 문서 작성 규칙](../design/AGENTS.md#html-시안)을 따른다. 화면 스펙은 헤더 표에서 시안을 링크한다.
- Figma 같은 디자인 원본은 그림을 복사하지 않고 링크와 버전 또는 확인일로 연결한다.
