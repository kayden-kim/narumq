# ADR 작성 규칙

[상위 규칙](../AGENTS.md)을 따르며 다음을 추가한다.

## 시작 템플릿

[ADR 템플릿](../templates/ADR-0000-template.md)을 사용한다. 파일명은 `ADR-NNNN-short-title.md`로 쓰고 번호를 재사용하지 않는다.

## 작성 규칙

- ADR은 `docs/decisions/`에 둔다. 다른 도구나 스킬이 `docs/adr/` 같은 위치를 제안해도 따로 만들지 않는다.
- ADR은 다음 세 조건을 모두 만족할 때만 만든다. 하나라도 빠지면 만들지 않는다.
  1. 되돌리기 어렵다. 나중에 생각을 바꾸는 비용이 크다.
  2. 맥락 없이 보면 의외다. 나중에 코드를 읽는 사람이 "왜 이렇게 했지?"라고 물을 만하다.
  3. 실제 대안을 비교했다. 얻는 이점과 감수하는 제약 때문에 하나를 골랐다.
- 구조·연동·기술·경계의 선택이라도 위 세 조건을 모두 확인한다.
- 채택된 결정(`Accepted`)의 결론과 당시 근거는 보존한다. 결론이 바뀌면 새 ADR을 만들고 이전 상태를 `Superseded`로 바꾼다. 두 문서는 서로 연결한다.
- 대안은 동일한 결정 요인으로 비교하고, 긍정적·부정적 영향과 후속 작업을 함께 기록한다.
- PRD, 스펙의 외부 동작, how-to 절차를 ADR에 복제하지 않는다.
- 업무 용어는 [용어집 유지보수](../AGENTS.md#용어집-유지보수)에 따라 ADR을 쓰는 시점에 확정한다.
